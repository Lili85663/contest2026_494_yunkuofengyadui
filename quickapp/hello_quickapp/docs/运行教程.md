# 腕上节律教练 3.2：从打开项目到使用

本教程取代旧版关于“25 分钟、快速体验、切换场景”的操作。那些按钮已删除。

## 首次在另一台 Ubuntu 电脑运行

本包是快应用工程，不包含 openvela 操作系统源码、SDK 镜像、依赖目录或密钥。不要用普通 C 文件运行按钮启动它。

1. 准备 Ubuntu 22.04、至少 16 GB 内存、40 GB 可用空间；安装 Git、Python 3、Node.js 22 和 npm。当前验证 Node.js 22.23.2，工具包版本由 package-lock.json 锁定。
2. 安装官方 AIoT IDE 和模拟器扩展。按[赛事健康接口指南](https://github.com/open-vela/docs/blob/dev-ai-contest-2026/zh-cn/contest_2026/quickapp/service_health_guide.md)准备健康镜像。本次验证扩展 1.7.22、镜像 vela-miwear-watch-5.0-beta（20260717）、ARM、480×480。
3. 在 IDE 创建名为 `wrist-rhythm-contest` 的虚拟设备。脚本通过 `~/.aiot-ide/extensions/vela.aiot-emulator-*/dist/emulator/index.js` 使用已安装 SDK；不要手工创建空目录冒充 SDK。
4. 将本包解压到无空格中文的路径，如 `~/wrist-rhythm`。进入该目录，执行下面命令。你的电脑上若已经安装好平台，从原教程第 2 节开始即可。

```bash
cd ~/wrist-rhythm
npm ci
bash scripts/setup-host.sh
python3 scripts/configure-mimo.py
systemctl --user restart wrist-rhythm-mimo.service
bash scripts/build-app.sh
bash scripts/deploy-app.sh
```

密钥由本人在终端隐藏输入，不随工程分享。没有密钥仍可使用直接计时和明确标注的本地计划。初次必须先部署，再运行 `python3 scripts/open-app.py`；仅打开未安装的应用不会自动安装。

比赛仓中，将本工程放在 `quickapp/hello_quickapp/`；保留组委会仓库已有 manifest、分支及提交配置。本包不是比赛系统分支的替代品。README、docs、logs 可随该目录保留，正式提交时在仓库根 README 链接作品说明，并将日志按官方要求归集到仓库根 logs。不要提交私有配置。

## 1. 项目在哪里

在 Ubuntu 打开 VS Code，选择“文件 → 打开文件夹”，打开 `/home/ma/wrist-rhythm`。它现在是专属仓 `quickapp/hello_quickapp` 的快捷入口，两者是同一份文件。迁移后请关闭旧文件夹再重新打开，避免编辑器还留在备份目录。

- 改页面文字、颜色、按钮布局：`src/pages/index/index.ux`。
- 改计时、休息、确认统计：`src/common/focusPlan.js`。
- 改学习计划提示词：`src/common/studyPlanner.js`。
- 改健康测试规则：`src/common/healthPolicy.js`，其中阈值不是医疗标准。
- 改本地健康文案：`src/common/healthAdvice.js`。

不要改 `build` 或 `dist` 中的文件，它们会在编译时重新生成。

## 2. 打开屏幕

现在统一使用已安装的官方赛事模拟器。Ubuntu 终端运行：

```bash
cd /home/ma/wrist-rhythm
python3 scripts/open-app.py
```

如果显示应用列表，点击“腕上节律教练”的帆船图标；进入应用后向上滑动解锁。没有表带装饰，显示纯色全屏应用。终端不要关闭，否则模拟器会退出。

## 3. 输入目标和分钟

1. 点击“编辑学习目标”。
2. 在点按键盘上组合常用中文词，例如“学习”＋“数学”＋“第一章”。
3. “切换：常用中文 / 英文 / 数字”可切换字符；“退格”删除最后一个字；“清空输入”重新输入。
4. 点击“输入完成”，上下滚动回到操作按钮。
5. 点击“修改分钟数”，先清空，再点数字，例如 3、0，最后点击“输入完成”。允许 5～180 的整数。

当前 Watch 组件不支持普通网页式文字输入框，因此使用应用内点按键盘。它支持常用中文组合和英文字母、数字，不是完整中文拼音输入法。总时长是净学习时间，休息另算。

## 4. 两种开始方式

### 不用 AI：按总时长直接开始

输入目标和分钟后点“按总时长直接开始”。例如输入 30 分钟，就启动一个 30 分钟的自主学习模块，不向 AI 发送内容。

### 使用计划：先生成，再同意

点击“生成 AI 学习计划”。通过 Ubuntu 本机转发服务，发送目标和分钟给 MiMo；未接通、超时或返回不合格时，使用本地两模块计划，页面明确标明来源。生成计划不会自动计时。

查看模块说明和分钟后点击“同意计划并开始”。不喜欢计划时，可修改输入重新生成，也可选择“按总时长直接开始”。

请求最长等待约 55 秒。只有显示“MiMo 学习计划”才是模型返回并通过校验；“本地计划”表示降级，不代表 AI 成功。

## 5. 计时、活动与自动恢复

- “暂停计时”：冻结当前学习或休息倒计时。
- “继续计时”：恢复暂停的阶段。
- 每累计学习 2 分钟，提醒一次（例如 2、4、6 分钟）“要不要活动 1 分钟”。选“继续专注”不暂停；选“开始活动”暂停学习，单独休息 60 秒。
- **休息结束自动恢复学习**，按用户最终要求实施。
- 手动暂停了休息，则需先继续休息计时；健康异常锁定时，休息结束也不能自动学习。
- 暂停和休息不累计学习时间。离开应用页面会暂停，回来需手动继续；不宣称后台健康监测。
- 模块到期后进入结果确认，不自动加次数。

## 6. 完成与未完成

点“提前结束，确认结果”，或等待计时结束，再选择：

- “完成，记录本次”：今日完成模块数加 1，学习时长按实际计。
- “未完成，保留实际时长”：完成数不加，但保留实际学习时间。

同一模块重复点击不会重复计数。确认后点击“开始下一模块”，不会自动跳到下一模块。

所有模块处理完后，显示“计划已结束，完成 X/Y 个模块”。这不代表所有模块都完成了。

## 7. 哪里看次数和保存情况

向下滚动到统计卡片：

- “今日确认完成 X 个模块”：用户确认完成的模块数量。
- “今日已记录学习 X 分钟”：包括完成与未完成记录的实际学习时长，不含未确认模块、不含休息。
- 内部按毫秒保存，界面合计后取整显示分钟，不足 1 分钟显示 0。
- 首版按确认日期归属当天，跨午夜在确认当天入账。
- “已保存到本机”代表成功；失败时计时暂停，可点“重试读取或保存”。

新版用独立存储键 `wrist-rhythm-v3`。旧版 `wrist-rhythm-v1` 没有删除，但不与新的手动确认统计混算。正常离开立即保存；运行时每 5 秒保存检查点，突然断电最多可能损失最后约 5 秒以及尚未完成写入的部分。

## 8. 健康提醒的真实状态

目前使用官方赛事健康模拟器，页面会显示心率、血氧和压力数值。它们是官方回放数据，不是你的身体测量结果；没有连接实体手表传感器。

从 `service.health` 订阅心率、血氧和压力，使用其 `timeStamp` 毫秒时间。模拟器上明确标“回放数据”，不等于本人实时测量。压力未参与判定。

有效新鲜样本明显异常时，本地代码立即锁定和暂停，不等待 AI。解除需要新的完整正常数据和用户确认；解除本身不自动继续。本地提醒立即生效。按当前需求开启了可选 AI 简短健康建议：异常时仅将当前有效指标及回放来源发给 MiMo，不发身份和历史。页面可点“关闭自动 AI 健康建议”，选择会保存。最多等 12 秒，失败保留本地建议；状态恢复会清除旧建议。这不是疾病诊断。

出现“本地计划”时，先看页面顶部的连接状态或点“检查 AI 连接”。计划来源是生成时的记录，不是实时连接状态。若当前计划尚未开始或已经结束，可再点“生成 AI 学习计划”。

## 9. 修改后怎样编译、安装

按 Ctrl+S 保存后，在 VS Code 终端执行：

```bash
cd /home/ma/wrist-rhythm
bash scripts/build-app.sh
```

脚本先运行测试，再打包整个 `src` 工程，不是只编译当前打开的文件。成功产物为 `dist/com.example.wristrhythm.debug.3.2.0.rpk`。

模拟器运行时，在另一个终端执行：

```bash
cd /home/ma/wrist-rhythm
bash scripts/deploy-app.sh
```

脚本会关闭旧应用、安装当前版本、重新打开，不用重启整个模拟器。如停在应用列表，点应用图标。编译本身不会更新模拟器，必须执行安装。

## 10. MiMo 配置和故障检查

当前采用“手表快应用 → Ubuntu 本机转发 → MiMo”的方式。模型为 `mimo-v2.5-pro`，上游地址为 `https://api.xiaomimimo.com/v1/chat/completions`。这是开发环境桥接方案，并非原生 `velaclaw` 已通过验收。

密钥已经在 Ubuntu 私有配置中设置，不在应用包或项目源码内。以后换密钥，在 Ubuntu 执行：

```bash
cd /home/ma/wrist-rhythm
python3 scripts/configure-mimo.py
systemctl --user restart wrist-rhythm-mimo.service
```

按提示输入，输入时不会显示字符。不要把密钥粘贴进代码。

检查服务：

```bash
systemctl --user status wrist-rhythm-mimo.service --no-pager
curl -s http://127.0.0.1:8765/status
```

`configured: true` 只代表已配置，不保证余额或网络正常；`bridge` 是不包含内容的调用计数。应用上显示“MiMo 学习计划”才代表这次调用成功。

快应用通过 `10.0.2.2:8765` 访问 Ubuntu；这个地址只用于当前模拟器。搬到实体手表时不能照搬，需要设备可用的安全转发服务，或比赛系统提供的原生 AI 接口。

未来若组委会提供包含 `@system.velaclaw` 的系统，可用 `bash scripts/build-contest.sh native` 构建原生适配包，再在该系统单独联调。现在默认构建使用已验证的桥接路径；不需要额外搜索服务密钥。
